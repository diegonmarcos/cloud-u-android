# Cloud Me

The personal-administration half of the constellation.

Cloud SuperApp is the launcher for everything the *cloud* runs. Cloud Me is the
launcher for everything the *person* runs: paperwork and money, what is due,
the public profile, travel, study — and health.

```
┌────────┬─────────────┬─────────┬─────────┬────────┬──────┬─────┐
│ Health │ Experiences │ Tasks │ Lnktree │ Inventory │ Buro │ LLC │   ← bottom nav
└────────┴─────────────┴─────────┴─────────┴────────┴──────┴─────┘
  Experiences = Work | Study (CV, Roadmap) | Personal Achieves (Geo, Endurance, Personal Growth, Community, By 30/40/50)
  top bar: ☰ left menu (tap only, no edge swipe) · right: AI · Profile · Configs (icons only)
  scrolling down hides the top bar and collapses the nav labels; scrolling up restores both
  page tabs: smaller than the nav, icon only (the selected one also shows its name), spaced evenly
```

## What it stores

Almost nothing. That is the design.

| Surface | Where the data actually lives |
|---|---|
| Buro → IDs & DD | the identity documents in `data/files/wallet/ids`, and the typed due-diligence checklist (`buro_user`) |
| Buro → Docs | typed Assets, Services, Liabilities & Taxes (`buro_user`; it absorbed House) |
| Buro → Financial Reports | typed budget lines, accounts and cashflow (`buro_user`); Budgeting and Accounts vs Cashflow are derived, never stored |
| Buro → Account | Cloud Account (launch tab, `extapp:cloud-account`) |
| LLC | typed employment, side-hustle income, company assets and holdings (`llc_user`); Income and Portfolio are derived |
| Tasks → Backlogs, Buro/LLC → Calendar | the cal engine — CalDAV events + VTODOs, read locally (Day, Subject, Calendar); Cloud Tasks writes |
| Me | `libs:wallet` — the same Me tab Cloud Wallet shows |
| Health | `libs:health` — Health Connect, on-device only |
| Experiences → Study, Work seeds, LLC history | `data/regen-study.py` from the bundled LinkedIn profile data (no LinkedIn API) |
| Inventory (City, Büro, Lifestyle rows; 16 pages) | `data/ui/inventory/<page>.json` — one item ledger per page over `inventory_user`, a summary header (count, value, monthly recurring) and a declared MOCK seed applied once (LedgerSeed), never over the owner's records |
| Experiences → Work | `data/ui/experiences/work.json` — Done and To do ledger over experiences_user, Done seeded with the profile roles |
| Tasks → RoadMaps | `data/repos/roadmap-tree.json` — the notes vault's folders, generated by `data/regen-roadmap-tree.py` from the committed `roadmap-tree.dirs.txt` snapshot (`--refresh` re-reads the vault through gh) |
| Experiences → Personal Achieves | `data/ui/experiences/achieves/<tab>.json` — Geo, Endurance, Personal Growth, Community, By 30/40/50: Done and To do ledgers over experiences_user (Geo with live stats), plus the owner's own text |

A second copy of a card, a password or a health record would be a second thing
to keep correct. Cloud Me indexes; the app that owns the data keeps it.

## Navigation is data

Every menu in the app is `build.json::ui.sections`, baked into
`BuildConfig.UI_SECTIONS_B64` and decoded once by `Sections.kt`. There is no
`res/menu`, no static tab list and no hardcoded tile array anywhere in the
Kotlin.

- Move Health into the bottom bar → `"bottom_nav": true` plus an `order`.
- Add a tab → one `pages` entry and the matching `stack_<page id>`.
- Add content → a block in that stack.

Block kinds the renderer understands: `section_title`, `note`, `stats`,
`cards`, `link_grid`, `about`, `permissions`, and `fragment` (hands the whole
page to a library module).

## Modules

Every `libs:*` is shared **by reference** out of `ab_cloud-libs-shared/libs`
via `build.json::modules[].dir` — this app owns no library source. A fix in
`libs:health` or `libs:wallet` lands here on the next build with no copy to
resync.

## Build

```sh
./build.sh build      # debug APK → dist/Cloud-Me.apk
./build.sh release    # signed release
./build.sh dev        # install + launch on the connected device
```

CI: `.github/workflows/ship-cloud-me.yml` (generated from
`1_cicd/src/cicd/ship-cloud-me.yml`) builds both ABIs, pushes the APK to GHCR
via ORAS and attaches it to the rolling GitHub Release. The app self-updates
from that image through `libs:updater`.

Fleet membership is automatic: `aa_cloud-superapp/data/regen.sh` scans every
sibling `build.json` and admits anything declaring `android.application_id`
plus `release.ghcr`, so Cloud Me registers itself in the constellation store
with no hand-maintained list to update.
